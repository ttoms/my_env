# RTL 对齐插件格式规范

> 本文所有"预期效果"示例均按第 4 节公式逐列计算得出，可直接作为实现的验收基准。

---

## 1. 默认设置

| 项目 | 规则 |
|---|---|
| 普通列对齐网格 | 4 |
| 非空字段之间的最小间隔 | 1 个空格 |
| 新增字段间隔 | 使用空格 |
| 列宽计算范围 | 当前对齐块，不跨独立块共享 |
| 列号起点 | 去掉块的前导缩进后，从 0 开始 |
| 原有语义 | 不改变标识符、表达式、常量、标点顺序或数组方向 |
| 重复执行 | 第二次结果应与第一次字节一致 |

**"按 4 列对齐"不是"每两个词之间放 4 个空格"。** 它表示普通字段的起始位置落在 0、4、8、12…… 这些网格点上；具体补几个空格由前面字段的长度决定。

涉及精确列数时，以 ASCII 代码字符为准。中文通常只出现在注释中，不应把列数直接等同于中文字形的屏幕显示宽度。

## 2. 如何划分对齐块

先划块，再计算列宽。

### 2.1 模块正文中的独立声明

连续的同类声明作为一个块，共同计算类型、维度、名称、分号等列的位置：

```systemverilog
logic a;
logic [7:0] data;
logic ready;
```

以下情况会结束当前块：

- 空行（包括只含空格或 Tab 的行）
- 中间出现其他代码，例如 assign、例化或过程块
- 声明类别改变，例如从 localparam 切换到 logic

**纯注释行**本身不占列宽，也不一定分块：

```systemverilog
logic a;
// Same declaration block.
logic longer_name;
```

这两条声明仍一起对齐。但有空行时必须分块：

```systemverilog
logic a;

logic longer_name;
// Independent declaration block.
logic b;
```

`b` 不应受 `longer_name` 的长度影响。

### 2.2 module 参数列表与端口列表

一个 module 中：

- `#(...)` 参数声明列表是一组
- `(...)` 端口声明列表是另一组
- 参数声明与端口声明**不混合**计算列宽

⚠️ 边界规则：同一参数列表或端口列表**内部的空行会保留，但不会将列表拆成多个对齐块**。

输入：

```systemverilog
module m #(
parameter int A=1,

parameter int LONG_NAME=22
)(
input logic a,
output logic longer_name
);
endmodule
```

预期效果（空行保留，列表仍按一组计算列宽）：

```systemverilog
module m #(
parameter   int A           =   1   ,

parameter   int LONG_NAME   =   22
)(
input   logic   a           ,
output  logic   longer_name
);
endmodule
```

> 注意这与正文独立声明的"空行分块"不是同一个范围规则。

### 2.3 模块例化

同一个例化的参数连接和端口连接**各自成组、不共享列宽**：

```systemverilog
child #(
.LONG_PARAMETER(8)
) u_child (
.a(data)
);
```

`.a` 的括号位置只由同组的端口连接决定，不受 `.LONG_PARAMETER`（参数组）长度影响。

- 不同实例之间不共享列宽
- 同一实例中，参数列表与端口列表之间的 `) u_child (` 会切断（分成两组，各自算列宽）
- 列表内部插入空行或纯注释，也不会拆分当前组的列宽

## 3. 缩进、换行及保留内容

### 3.1 缩进

对齐块内：

1. 取第一条实际参与对齐的代码行的前导缩进
2. 其他参与行使用相同缩进
3. 在这个缩进后计算字段列位置
4. 空行和纯注释行不作为缩进基准

> 如果第一条声明使用一个 Tab，后面一条使用八个空格，当前结果会统一使用第一条声明的 Tab。

因此：

- 插件不是全文件缩进规范化工具
- 它不会一律把已有缩进改成四个空格
- 要稳定的视觉效果，输入代码仍应使用一致的空格缩进

### 3.2 一条声明／连接一行

> ⚠️ 当前插件未实现此特性（不拆行、不合并行），逐行处理，此节仅描述目标行为。

目标行为是把可识别的列表整理成：

- 一个参数声明一行
- 一个端口声明一行
- 一个命名参数连接一行
- 一个命名端口连接一行

原本写在同一行的项目可以拆开；一条项目内部没有注释干扰的跨行表达式，可以合为一行。

⚠️ 但不应据此推断它会统一所有外层标点空白。例如 `)(` 与 `) (` 当前可能继续保留不同写法，不能假定它必然统一成后者。

### 3.3 不做的事情

对齐不包括：

- 自动添加 logic、位宽或类型
- 自动调整参数顺序
- 改变 packed／unpacked 布局
- 把 `[0:N-1]` 改成 `[N-1:0]`
- 将复杂表达式提取为中间信号
- 重排所有运算符周围的空格
- 自动换行以满足最大行宽
- 改写注释正文

## 4. 精确的列位置计算规则

要根据文字复现当前结果，需按下面的方法计算，而不是靠视觉估计。

### 4.1 先确定每一列的宽度

对一个块中的每一列：

> **列宽 = 该列所有行中最长非空字段的长度**

- 某行缺少字段时，该行该列为空，不输出占位文本
- 如果整列都为空，其宽度为 0

### 4.2 普通列的起始位置

定义：

- `Sᵢ`：第 i 列起点
- `Wᵢ`：第 i 列最大字段长度
- 第一列 `S₀ = 0`
- 默认最小间隔为 1

普通情况下：

**下一列起点 = 不小于「当前列起点 + 当前列宽 + 1」的最小 4 的倍数**

公式：

```
Sᵢ₊₁ = 4 × ceil((Sᵢ + Wᵢ + 1) / 4)
```

例如前一字段从位置 8 开始，宽度为 5：`8 + 5 + 1 = 14`，向上取到 4 的倍数 → 16，下一列从位置 16 开始。

### 4.3 整列为空

如果一整列宽度为 0：

```
Sᵢ₊₁ = Sᵢ
```

即不为所有行都不存在的字段额外增加一段空白。

注意两者不同：

- 整块都没有维度：不预留维度区域
- 只有某一行没有维度：仍需保留其他行所需的维度区域，以便名称对齐

### 4.4 左对齐与右对齐

默认所有字段**左对齐**，只有 packed 维度后缀列**右对齐**。

- 左对齐：字段起点放在该列起点
- 右对齐：字段末尾放在该列统一右边界（`Sᵢ + Wᵢ`）

右对齐列中的短字段，左侧增加空格：

```
额外左补空格 = 该列最大宽度 − 当前字段长度
```

如果两段实际输出字段之间按目标位置算出的间隔不足 1，至少保留 1 个空格。

### 4.5 packed 维度链的紧凑间隔

**类型 → 第 1 维前缀、前缀 → 后缀、后缀 → 下一维前缀**，这几处间隔均为"前一列末尾 + 1"，**不**向上取整到 4 的倍数。即整个 packed 维度链内部只用单空格连接。

**维度链之外**（方向 → 类型、后缀 → 名称、名称 → 尾部等）仍使用普通的 4 列网格规则。

因此正常多维声明中，两个 `] [` 之间只留 1 个空格，例如 `logic [3:0] [15:0] matrix` 排为 `[3   :0] [15 :0]`。

> 因此第 1 维前缀的 `[` **不在** 4 格倍数的列上——它紧跟类型字段（单空格），而非独立对齐到网格。这是有意为之：让 `logic [7:0]` 读成一体，只有方向、名称这类「字段边界」才对齐 4 格。

## 5. packed 维度如何拆分和对齐

### 5.1 每个维度拆为前缀和后缀两列

| 原始维度 | 前缀（左对齐） | 后缀（右对齐） |
|---|---|---|
| `[WIDTH-1:0]` | `[WIDTH` | `-1:0]` |
| `[DEPTH-12:2]` | `[DEPTH` | `-12:2]` |
| `[7:0]` | `[7` | `:0]` |
| `[N:1]` | `[N` | `:1]` |

拆分规则：紧贴十进制数字的末尾 `-1`、`-12` 归入后缀；前缀是 `[` 到后缀之前的部分。

> 数字位宽没有 `-1`，不意味着直接写成紧凑的 `[7:0]`。它的 `:0]` 仍需和其他行的后缀右边界对齐。

### 5.2 对齐的是整个后缀右边界

输入：

```systemverilog
module m (
input logic [WIDTH-1:0] a,
input logic [7:0] b,
input logic [DEPTH-12:2] c
);
endmodule
```

预期效果：

```systemverilog
module m (
input   logic [WIDTH  -1:0] a
input   logic [7        :0] b
input   logic [DEPTH -12:2] c
);
endmodule
```

观察重点：

- 三个 `[` 在同列，三个 `]` 在同列
- `-1:0]`、`:0]`、`-12:2]` 长度不同，所以前面补空格不同（`]` 统一对齐到后缀列右边界）
- **不是**要求减号在同列，也**不是**单独把冒号当成统一列
- 本例聚焦维度对齐，省略了端口末尾的逗号（实际按 §6.3 处理逗号）

### 5.3 多维 packed 数组逐维独立计算

```systemverilog
logic [NUM_REQ-1:0][DATA_WIDTH-1:0] payload;
```

字段为：

```
类型 | 第1维前缀 | 第1维后缀 | 第2维前缀 | 第2维后缀 | 名称 | 分号
```

同一组各行按第 1 维、第 2 维……分别求最大宽度，不能把整段多维范围当成一个大字段。

### 5.4 缺少维度的行

块内存在二维声明时：

- 一维声明只填第 1 维，缺少第 2 维
- 标量声明缺少全部维度
- 缺失维度的位置保留为空，以便名称统一对齐

输入：

```systemverilog
wire [W-1:0] a;              // one
logic signed [7:0] longer;   // two
logic [3:0][15:0] matrix;
logic ready;
```

预期效果：

```systemverilog
wire         [W -1:0]           a       ;   // one
logic signed [7   :0]           longer  ;   // two
logic        [3   :0] [15 :0]   matrix  ;
logic                           ready   ;
```

`ready` 前的大段空白是为同组类型和维度预留的位置，不是无缘无故添加空格。

### 5.5 范围表达式内部空白

范围表达式内部的空格会被移除、规范化。例如 `[W - 1: 0]` 与 `[W-1:0]` 得到相同排版（都排成 `[W -1:0]`）：

```systemverilog
logic [W -1:0]  spaced  ;
logic [W -1:0]  tight   ;
```

拆分规则不受输入空格影响：拆分点始终是"紧贴数字的 `-` 或 `:`"（见 §5.1）。

> 注意：`[W - 1: 0]` 若本意是把 `W - 1` 当作一个减法表达式（而非"`W` 参数、`-1:0` 范围"），拆分仍按 §5.1 把 `-1` 归入后缀。这类歧义属于输入写法约定，对齐器不做语义判断。

## 6. module 端口声明的列规则

端口声明按以下顺序拆列：

```
方向 | 类型及修饰符 | 各packed维度前缀/后缀 | 名称 | 尾部标点 | 行内注释
```

### 6.1 方向

`input`、`output`、`inout`、`ref` 共用方向列，左对齐。

- 如果同组含 `output`，方向列宽为 6；否则为 5（仅 `input` 时）
- 默认网格下，类型列从相对位置 8 开始，即：

```text
input   logic
output  logic
```

### 6.2 类型

以下内容按**一个类型字段**处理：

```
logic
wire
logic signed
logic unsigned
FLIT_T
pkg::flit_t
```

- 类型字段左对齐
- signed／unsigned 不再独立成为一列
- 类型缺省的行留空，不自动补类型
- 自定义类型与内置类型使用同一列

### 6.3 名称与逗号

- 端口名称左对齐
- 名称列宽由同组最长名称决定
- 逗号单独一列
- 最后一项没有逗号时，不补逗号，也不输出为了逗号列而产生的行尾空格

### 6.4 实际效果

输入：

```systemverilog
module m #(
parameter int W = 8,
parameter logic [7:0] RESET = 8'h00,
parameter N = 4
)(
input logic clk,
input logic [N-1:0][W-1:0] data,
output logic [7:0] result,
output logic valid
);
endmodule
```

预期效果：

```systemverilog
module m #(
parameter   int         W       =   8       ,
parameter   logic [7:0] RESET   =   8'h00   ,
parameter               N       =   4
)(
input   logic                   clk     ,
input   logic [N -1:0] [W -1:0] data    ,
output  logic [7   :0]          result  ,
output  logic                   valid
);
endmodule
```

> 参数列表的类型列与端口列表的类型列**独立计算**，两者后续字段不需要纵向连成同一列。

## 7. parameter／localparam 声明规则

参数声明按以下字段排列：

```
关键字 | 完整类型 | 参数名 | = | 值表达式 | 逗号 | 行内注释
```

### 7.1 类型作为整体

参数类型中的 packed 位宽**不使用**端口那种前缀／后缀拆列：

```systemverilog
parameter logic [7:0] RESET = 8'h00
```

其中 `logic [7:0]` 是一个完整类型字段。

### 7.2 参数名称、等号、值

- parameter 与 localparam 是关键字字段
- 参数名左对齐
- `=` 单独一列
- 默认值表达式整体左对齐
- 不自动整理值表达式内部运算符空格

### 7.3 参数列表逗号单独对齐

```systemverilog
parameter   int A           =   1   ,
parameter   int LONG_NAME   =   WIDTH + 1
```

短值 `1` 后可能出现较长空白，这是为了让列表中的逗号单独成列。

### 7.4 正文 localparam 的分号单独拆列

模块正文里的 localparam/parameter 声明块同样对齐（关键字 | 类型 | 参数名 | = | 值 | 分号）。

输入：

```systemverilog
module m;
localparam int A = 1;        // a
localparam int LONG_NAME = N + 20;  // b
parameter int X = 2;
localparam int WIDTH = 32;   // c
endmodule
```

预期效果：

```systemverilog
module m;
localparam  int A           =   1       ;   // a
localparam  int LONG_NAME   =   N + 20  ;   // b
parameter   int X           =   2       ;
localparam  int WIDTH       =   32      ;   // c
endmodule
```

- `=` 和值起点对齐
- `;` 单独一列对齐（与 §8.1 普通信号声明的分号处理一致）
- 值与分号不再同属一列

## 8. 模块正文信号声明规则

信号声明按以下字段排列：

```
类型及修饰符 | 各packed维度前缀/后缀 | 名称 | 尾部字段 | 行内注释
```

没有端口方向列，其余 packed 维度规则与端口一致。

### 8.1 普通声明

普通声明的尾部只有分号时，分号单独对齐：

```systemverilog
logic [7 :0]    a           ;
logic           long_name   ;
```

### 8.2 带初始化的声明

`=` 单独一列对齐；`值 + 分号 + 注释` 作为**整体尾部**，不进一步拆成"等号、值、分号"三列。

```systemverilog
logic [7 :0]    a           = 8'h00; // a
logic           long_name   = 0; // b
```

可保证尾部起点统一，但**不保证**：

- 初始化值后分号对齐
- 这类尾部内的注释对齐
- 初始化表达式内部空格统一

### 8.3 unpacked 数组

变量名后的 unpacked 维度**不按** packed 维度规则拆列，也不会被移动到变量名前：

```systemverilog
module m;
logic [7 :0]    packed_data ;
logic           mem         [0:3][0:3]; // memory
endmodule
```

- `mem` 与其他信号名称共列
- `[0:3][0:3]; // memory` 属于名称后的整体尾部
- 不会自动在两个 unpacked 维度之间补出 packed 风格的 `] [`
- 是否应改成左侧 packed，是 RTL 设计规则，不是格式化行为

## 9. 模块例化连接规则

每条命名连接拆成三列：

```
.参数名或端口名 | (连接表达式 | 右括号及其后内容
```

例如 `.payload(data_bus),` 拆成 `.payload` | `(data_bus` | `),`。

### 9.1 左括号属于连接表达式列

`(` 与表达式之间不人为加空格：

- ✅ `.payload(data_bus   ),`
- ❌ `.payload( data_bus  ),`

### 9.2 右括号独立对齐

根据同组最长的 `(表达式` 字段，统一确定右括号起点：

- 短表达式后补空格
- 逗号紧贴 `)`，形成 `),`
- 不在 `)` 与逗号之间插空格

### 9.3 参数和端口各自决定列宽

输入：

```systemverilog
module m;
child #(
.W(8),
.LONG_PARAMETER(N + 1)
) u_child (
.clk(clk),
.payload(data_bus),
.unused()
);
endmodule
```

预期效果：

```systemverilog
module m;
child #(
.W              (8          ),
.LONG_PARAMETER (N + 1      )
) u_child (
.clk            (clk        ),
.payload        (data_bus   ),
.unused         (           )
);
endmodule
```

- `.LONG_PARAMETER` 撑宽了参数组的连接名称列（不影响端口组）
- `data_bus` 等最长连接内容参与右括号列计算
- 空连接不是紧凑的 `()`，而是左括号、必要填充、统一右括号

### 9.4 嵌套表达式

连接表达式中已有的函数调用、拼接、索引和嵌套括号保持其内容，不改变表达式语义。例如 `.d(make_value(a, b))`，内部 `make_value(a, b)` 不拆成多条连接，也不因其中的逗号而换行。

### 9.5 例化行尾注释

例化连接的行尾注释遵循 §10.2：注释作为**独立的一列**，按普通列网格对齐。

- 右括号列对齐，逗号紧贴 `)`（形成 `),`）
- 注释单独一列，所有行的注释起点对齐（含末项，末项无逗号时注释列位置仍与其余行一致）
- 没有注释的行不补尾随空白

```systemverilog
.A          (1  ),  // a
.LONG_PARAM (2  )   // b
) u_x (
.a          (x  ),  // aa
.long_port  (y  )   // bb
);
```

## 10. 注释、空字段与保留行

### 10.1 纯注释

纯 `//` 注释行：

- 保留原文及位置
- 不参与字段宽度计算
- 不会因为注释很长而撑宽代码列
- 正文声明间只有注释、没有空行时，两边声明仍可能同块

### 10.2 行内注释

对端口声明、无初始化的信号声明、参数声明、例化连接：

- 行内注释可作为最后一列
- 注释开始位置按普通列网格计算
- 注释正文不翻译、不自动折行
- 没有注释的行不补一段尾随空白

> 初始化声明（8.2）、unpacked 尾部（8.3）的注释受整体尾部规则限制（贴尾部、不单独对齐），不套用本条。

### 10.3 保留标记

带当前保留标记的行**不参加列宽计算，保持原样**。默认标记配置为 `keep`。这类行不是"按其他行排好以后再恢复内容"，其字段长度也不应影响其他参与行。

### 10.4 所有行都缺失的字段

整列为空时不占空间；某一行缺失时保留相应逻辑列位置。这解释了两个常见效果：

- 全部标量声明可以很紧凑
- 标量混入多维声明块时，会出现较大留白

## 11. 不同操作入口的范围差异

各入口共享基本列布局效果，但"选哪些行一起排"并不完全相同：

| 操作方式 | 范围规则 |
|---|---|
| module 声明对齐 | 在选中的 module 声明范围内，参数列表和端口列表分别成组 |
| 标记式信号块对齐 | 从标记对应的信号声明开始，到空行或非声明代码结束 |
| 手动选区对齐 | 选区内同类参与行按一次操作共同计算；空行本身跳过，但不应假定自动拆成多个块 |
| 单次例化对齐 | 选中范围内的连接按一组共同计算（不自动拆参数/端口组） |

## 12. 按文字复现的操作顺序

全部规则可压缩成以下可执行顺序：

1. **确定入口和处理范围**
2. **划分对齐块**：正文独立声明遇空行分块；module 参数／端口列表分别成组；单个实例的参数与端口各自成组
3. **整理为一行**：每条声明或连接一行，保留必要注释和外层结构，不改 token
4. **取缩进**：块内第一条参与行的缩进
5. **拆字段**：按类别使用各自的字段表（参数、端口、信号、例化）
6. **逐维拆 packed 范围**
7. **补空字段**：为缺失维度补空，使名称列对齐
8. **逐列取块内最大字段长度**
9. **计算列起点**：普通列向上取整到 4 的倍数；packed 维度链内部用紧凑间隔（见 4.5）
10. **输出字段**：默认左对齐，packed 后缀右对齐；非空字段间至少一格
11. **不输出无实际内容的尾随填充**
12. **保留**不在处理范围内的代码
13. **幂等**：再次执行应无变化，且 token 与注释内容保持一致
